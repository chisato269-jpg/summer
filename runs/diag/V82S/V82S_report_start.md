## 5. G-0R の結果と、実装で置いた補足

### 5-1. G-0R（`g0r/g0r_result.json`）

| 項目 | 値 |
|---|---|
| 始点の軌跡の再生（V8 の環境、1 エピソード） | E `0x1.1aea1a9fbe76dp+2`・DR `0x1.6c1d5c0000000p-3` で、記録と 16 進一致（教師の観測・マスク・行動を記録） |
| 教師の有効な判断の数 | 20,676（378 ステップ × 80 次元のうち） |
| 学習の前に一致していなかった判断 | 15 判断（ロジットの差が 1e-3 未満のものは 16 判断。差が 0.0 の同点が 1 判断） |
| 学習の結果 | 300 エポックで一致せず、一致しない判断が **28 判断**に増えた（最小のロジットの差 −25.6）。採用せず、学習前の重みに戻した |
| 分岐 | 学習前の重みの基準の軌跡を始点にした。E `0x1.1a204189374bcp+2`、DR `0x1.6cd5d80000000p-3`、ECI 0.710330 |
| 方策の重み | `~/rl_models/v8s_trial02/g0r_policy.pt`（学習前の重みのまま。`reproduced: false` を記録） |

不一致の 16 判断の内訳（学習の前）: 風量 7、設定温度 3、割合 3、蒸発温度 1、リモコン 1、換気 1。ロジットの差は −34.6、−26.4、−25.1、−25.0、−18.4、−16.9、−15.1、−13.5、−11.5、−10.5、−9.8、−4.3、−4.3、−4.0、−3.3、0.0。ステップは 191 と 322〜333 に集まる。つまり、兄弟の変更（まばらの確率 0.03 で選び直した 16 判断）は、方策が確率最大とする選択から、ロジットで 3〜35 離れた選択を一様に選んだものだった（16 判断のうち 11 判断が差 9 以上）。

学習で動かせなかった理由は、推測です: 学習率 3e-4 の Adam で 300 エポックは、パラメータの動きが各 0.09 程度までで、ロジットを 10〜35 動かすには足りない。全判断（20,676）の平均の交差エントロピーで、既に一致している判断が大半を占め、変更した 16 判断の信号が薄い。16 判断を動かすパラメータの更新が、他の判断を崩して、一致しない判断が 28 に増えた。

### 5-2. 実装で置いた補足（V82S-a）

指示書は「有効な判断」から「環境に書き込まれない判断」を除く。割合 0 のゾーンの設定温度は環境に書き込まれず、観測にも入らない（観測のゾーン +19 は割合 0 のとき 0）ので除いた。一方、割合 0 のゾーンの風量は環境には書き込まれないが、観測のゾーン +20（直前の風量）に入り、次のステップの観測を変えるので、**教師に含めた**。含めないと、方策の確率最大の選択がそこだけ違うために次のステップの観測が変わり、軌跡が再現されない（L-7R の目的に反する）。指示書の文言より少し広い。
